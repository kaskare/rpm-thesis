Expressiveness Is Not Trainability

Porting a relational GNN from PyTorch to a differentiable logic program. The relational structure transfers cleanly; the optimisation machinery does not. Given the right split, with PyNeuraLogic doing message passing and scoring and PyTorch doing embeddings and optimisation, the port reaches 68.5% on I-RAVEN across all seven constellations, the same end to end through a ResNet-18. The torch GNN, retrained over three seeds with both pipeline bugs fixed, averages 45.3%; its old published 68.8% was trained on wrongly decoded positions and cannot be reproduced. A separate symbolic template, with no embeddings at all, reaches 98.3% on the test split with ground-truth attributes and 96.3% end to end.

A symbolic template

A different PyNeuraLogic model with no embeddings and no message passing: attribute values, rows and slot sets are symbols, crisp rules derive which relations hold on each row, and learned weights score each candidate row (pynl_symbolic.py). On the test split it reaches 98.33% with RAVEN's rule families and 97.55% with a generic vocabulary of primitives, with ground-truth attributes; end to end through the same ResNet-18 it reaches 96.31% and 95.71%. The end-to-end loss sits entirely in the two constellations where perception is imperfect (distribute_nine 95.5% → 85.4%, in_distribute_four_out 97.3% → 93.2%). Non-learned solvers over the same vocabularies reach 97.78% and 96.42%. Ten training puzzles per constellation already lift the primitives above plain counting, and three random initialisations all converge to the same accuracy. The learned primitive weights rediscovered the rules (position union and colour addition weighted highest). Its relations are designed rather than learned, which is the price of the accuracy.

Still open

PyNeuraLogic has one seed, against a torch GNN that varies from 35% to 59% across seeds. Running since 19 Oct: five GNN ablations aimed at the weak spot, puzzles where the set of occupied slots changes (row/column edge labels, within-panel edges with their own weights, position-aware empty slots).

1.1  RAVEN's answer-set leakage, measured

Benchmarkobject_only+ unifiedΔ
RAVEN81.09%96.45%+15.4
I-RAVEN68.44%48.28%−20.2
 Same code, same hyperparameters, sign flip.

RAVEN builds its eight candidates by perturbing the correct answer one attribute at a time, so the answer is the attribute-wise centroid of the candidate set, recoverable without looking at the context at all. unified_graph puts all eight candidates in one graph where they exchange messages, which is exactly the mechanism needed to exploit that. I-RAVEN removes the bias, and there the same mechanism costs twenty points.

Consequence

96.4% is not a real number. Any port should target the I-RAVEN config and keep candidates from seeing each other. The I-RAVEN 68.8% turned out not to be valid either: it was trained on the corrupted positions of §10, and the retrain with both fixes averages 45.25% over three seeds.

1.2  The winning architecture

emb 256 / hidden 384 / 3 layers / lr 1e-3 / dropout 0.1 / batch 8 / AdamW wd 1e-4

  • Graph: 8 context panels + 1 candidate, one graph per candidate. Objects only. 17 typed relations.
  • Encoder: a plain sum of embedding lookups over pos, color, shape, size, kind, role, panel-grid.
  • Layer ×3: msg = W([x_src + rel_emb ; x_dst ; rel_emb]), scatter_mean per destination, then LayerNorm(x + dropout(out_proj(agg))).
  • Loss: one 8-way softmax ranking the candidates. The non-unified path still scores each candidate on its own graph, then stacks: independent scoring, joint normalisation.

03Framework traps

Each cost real debugging time. None produces a clear error message.

  1. Embedding tables must be declared as weighted facts. A body atom with no matching facts silently fails to ground; you get Query not matched anywhere in the template, which points at the wrong place entirely.
  2. Every sample needs a unique query atom. With a nullary query all eight candidates share one identity and PyNeuraLogic merges them: 3440 samples came back as 2240, with no error. This also means duplicating samples to oversample positives does nothing; copies are deduplicated.
  3. build_dataset() may be called only once per built model. The second call throws ArrayIndexOutOfBoundsException.
  4. Aggregation.CONCAT does not emit in the order you named the constants. It uses the grounder's own permutation, [6,0,4,3,1,2,7,5] here. Uncorrected, the head scores candidate i against candidate j's target and the model cannot learn. The order depends only on the constants, not template depth, so a depth-0 companion can be probed to recover it.
  5. Rules sharing a head combine with SUM; AVG applies within one rule, over its groundings.
  6. Constant tensor inputs need requires_grad=True, or autograd never records the node and backward never reaches the template weights.
  7. Weight sharing across topologies breaks backward. Two modules from one Model do share weights and forward correctly, but the second topology's backward throws a dimension error, because trainer state binds to whichever topology grounded first.

4.1  Expressing 8-way softmax in PyNeuraLogic

It is possible, and worth recording:

m += (R.answer(V.G) <= (R.cand_of(V.B, V.G), R.score(V.B))) \
     | Metadata(aggregation=Aggregation.CONCAT)     # 8 scalars -> one 8-vector
Sample(R.answer(gid)[onehot], facts)                 # target as one-hot
Settings(error_function=CrossEntropy(with_logits=True))  # softmaxes internally

One sample is one puzzle, with all eight candidate sub-graphs present but fully disjoint: context duplicated per branch, no candidate-candidate edges. That reproduces the torch path exactly and avoids the leakage. At full scale it never learned.

Moving the scoring head into PyNeuraLogic helped: level 2 beat level 1 by 6.4 points. Readout, context pooling and per-candidate scoring are all learnable as rules.

The collapse is entirely 2 → 3: −18.2 points. That step moves only the attribute embeddings from nn.Embedding into a [d, n_values] matrix over a one-hot, mathematically the same operation. The further 3 → 4 drop of 5.4 isolates the training loop as real but secondary.

Train loss says it more sharply: levels 1–2 reach ~0.2, while level 4 never fits the training set at all (1.402 against a 2.079 uniform floor).

Caveat

Single seed per level. The 18-point 2→3 gap is unlikely to be noise; the 6.4-point 1↔2 ordering could plausibly flip. Worth three seeds before citing.

8.1  The uncomfortable implication

In this hybrid, the symbolic component is reduced to pure topology: a message-passing schedule over a fixed graph. No attribute constants, no grounding over attribute values, no logical embeddings. All semantic content lives in torch. And that is the version that works.

The more of the symbolic machinery moved out of PyNeuraLogic, the better it performed. A reviewer will ask what the logic is buying; for the 52.9% model the honest answer is "the graph topology, and not much else". The pure version is the one that actually does neurosymbolic reasoning, and it is stuck at 27.2%. That contrast is the result. The final level-2 model shifts the balance back somewhat: its scoring head is also written as rules, and PyNeuraLogic holds 87% of its parameters.

Slot semantics

Slot k is the k-th universal position of that constellation, not the k-th object present. A puzzle is entirely one constellation, so slot k denotes the same position in all sixteen panels and same-slot cross-panel edges link matching positions. Verified across 4243 objects, zero mismatches.

9.1  Overfit probe, all seven at once

92.9%: thirteen of fourteen puzzles memorised, six constellations at 100% including distribute_nine. Only distribute_four stuck, at 50%.

Isolating it: five puzzles, saturating at 80%, loss flat at 0.4159 for 150 epochs. And ln(8)/5 = 0.4159 exactly, so four puzzles are fit perfectly and one sits at precisely uniform. The model emits identical logits for all eight candidates on it. That signature led directly to the next section.

10The position bugs

Two decoding bugs in the original torch pipeline, not only in the port. The slot bug (10.1–10.2) is specific to I-RAVEN; the spatial-relation bug (10.3) affects both datasets.

parse_ground_truth derived an object's slot from all_positions.index(bbox), where all_positions is the layout's XML Position attribute. The two datasets write that attribute differently:

DatasetPosition listsPosition.index(bbox) isBug
RAVEN-10000every slot of the layoutthe true slotdormant
I-RAVEN-10000only the occupied slotsrank among present objectslive
 
distribute_four, one panel     RAVEN:   3 objects, Position lists 4 bboxes

I-RAVEN's generator rewrites the XML when it rebuilds the candidates, and in doing so shrinks Position to the occupied slots. Code written and tested against RAVEN is correct there and silently wrong on I-RAVEN, which is how it went unnoticed. For any panel holding fewer objects than the constellation's maximum, position identity is destroyed: a lone object at slot 3 and a lone object at slot 0 both become local index 0.

10.3  Third bug: wrong spatial relations in the torch graph

The torch graph types within-panel edges by spatial relation (left_of, above, same_row, overlap …). infer_relations looks each object's centre up by its universal position id, but build_position_centers keyed centres by the rank of each bbox in a sorted list of all bboxes, a different numbering, and also treated the centre-based bboxes as corner-based. The panel centre, universal position 0, was given (0.33, 0.33) instead of (0.5, 0.5).

distribute_four33.4%4→2: below, left_of vs below, same_col
distribute_nine75.1%7→10: above, left_of vs above, same_col

It affects every torch GNN run, on RAVEN and I-RAVEN, published and retrained. The labels are wrong but consistent, a fixed function of the position pair, so the GNN could still use them as arbitrary edge types; distinct geometric relations get merged, though, and no claim about spatial reasoning can rest on those models. The PyNeuraLogic model uses no spatial relations and is unaffected.

Fix: universal_position_centers() takes each universal position's centre from its bbox geometry. The trainer uses it by default (--legacy-centers restores the old behaviour), and eval_gnn_test.py now evaluates with the centres stored in each checkpoint, so every old checkpoint reproduces its reported number exactly. With the fix, no relation is wrong in any constellation. The retrain with both fixes runs over three seeds (submit_gnn_fixrel.sh).

10.4  Rotation is not a missing attribute

Angle sits on every entity and is captured by neither pipeline. Across 420 puzzles in all seven constellations, the rules govern only Type (660), Size (660), Color (660), Number/Position (506), Number (81) and Position (73). Angle appears zero times. It is a noise distractor, so dropping it is correct, and after the position fix no candidate collisions remain without it.

11End to end

Everything above reasons over ground-truth attributes read from the XML. Here the XML is replaced by what a ResNet-18 sees in the images.

11.1  The perception frontend

An NVSA-style universal frontend (train_frontend.py), trained on RAVEN-10000, all seven constellations jointly.

  • Input: one panel at a time, 160×160 grayscale, repeated to 3 channels for the ImageNet-pretrained ResNet-18. First conv stride 1 and no max-pool, so small objects keep their resolution. Output: a 512-d vector per panel.
  • Targets: a frozen random codebook of 6622 rows, one per combination of 22 positions × 5 types × 6 sizes × 10 colours, plus one "object here" row per position. Each row is the element-wise product of four random ±1 vectors (type ⊙ size ⊙ colour ⊙ position). Only the ResNet trains.
  • Loss: cosine similarity to every row under the NVSA paper's additive cross-entropy, one term per object, averaged. A multi-object panel learns to output the superposition of its objects' vectors.
  • Best checkpoints: …_mean3 at 95.26% panel accuracy and …_mean1 at 95.04%.

11.2  The pipeline

StageWhereDoes
perceiveGPU, env nvsaruns both frontends over every I-RAVEN val and test panel (448,000) and scores perception against the ground truth. 10 minutes on one A100; outputs cached.
solveCPU, env pynlpicks the frontend with better val perception, decodes its test detections, and scores the same puzzles end to end and with XML labels, with the same checkpoint. About 90 minutes.

At each position the constellation uses, the best of its 300 attribute rows is taken, and the object exists if that cosine exceeds 0.23, the frontend's training threshold. The frontend's position IDs, PyNeuraLogic's POS_MAP and the ground-truth parsers are identical, so detections need no remapping.

11.5  Can the whole thing be trained end to end?

Technically yes. Exactly one step blocks gradients:

pixels → ResNet → cosine vs codebook → [threshold + argmax → integer IDs] → embedding lookup → PyNeuraLogic → 8 logits
                                             ↑ the only non-differentiable step

The fix is to replace the hard decode with soft attribute probabilities: per position, a softmax over the 300 codebook similarities, collapsed into P(type), P(size) and P(color), plus a soft existence probability. The node embedding becomes the probability-weighted sum of the embedding rows, blended with the pad token by the existence probability. With certain probabilities this reproduces the current model exactly, which gives a clean regression test. It is the same trick NVSA's own end-to-end training uses (raven/main_nvsa_marg.py).

Everything downstream already passes gradients: level 2 trains its torch embeddings through the PyNeuraLogic layer, and training runs backward once per puzzle. A GPU node (A100, 128 CPUs, 1 TB RAM) holds the ResNet and the JVM side by side, and speed would be set by the reasoner at ~6.3 h per full-data epoch.

The catch

Perception costs 0.03 points, and joint training can at best recover what perception loses. The limit is the reasoner, at 68.5% even with perfect inputs. End-to-end training buys a methodological claim, fully differentiable end to end, rather than a better number.

13Open questions

  1. A trustworthy torch baseline. The published run can't be reproduced and both existing torch models used wrong spatial relations. The three-seed retrain with both fixes settles the baseline and its spread.
  2. The reasoner is now the bottleneck, not perception. Re-measured at epoch 62: distribute_four and distribute_nine score 66–69% when the layout stays constant and about 30% otherwise. Number rules sit at 26–29% and Position-Progression is worst at 18–22%. The model handles attribute rules and fixed layouts and fails when the set of occupied slots changes. Panel layout features and within-panel edges both hurt when tried.
  3. A from-scratch full-data run. The 64% model is a warm start from the 2000/constellation one.
  4. End-to-end training (§11.5): version 1 is low-risk and earns the claim; version 2 is the research question.
  5. Why can't PyNeuraLogic learn input embeddings? The narrow failure from §7. Initialisation and gradient scale on fact-weight matrices are the place to look.
  6. Seeds. Every PyNeuraLogic number here is a single run; the torch baseline now gets three.
A framing that fits the evidence

GNNs are provably a special case of differentiable logic programming, and that equivalence invites the assumption that anything a GNN learns, a template can learn. These experiments show that is false in practice, and localise why: the declarative part transfers cleanly, while normalisation, skip topology, batching and embedding optimisation, none of which the framework gives you vocabulary for, are what make deep GNNs trainable. Hand those parts to PyTorch and keep the relational reasoning and scoring as rules, and the logic program outperforms the GNN it was ported from.

The leakage ablation (§1.1) and the position bug (§10) are independently publishable observations about the benchmark and its standard tooling.
